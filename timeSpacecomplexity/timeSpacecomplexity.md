# Big-$O$ Complexity ($O$ Notation)

Big-$O$ describes the **Upper bound** or worst-case performance of an algorithm as the input size(*N*) grows towards infinity.

## Common Big-$O$ orders(from best to worst)

$O(1)$ Constant time....takes exact same amount of time regardless of input size(eg., accessing an array element by its index)

$O(log N)$ Logarithmic time ... The problem size if halved with each step.(e.g., Binary search)

$O(N)$ Linear time: Performance grows linearly with the input size(looping through an array once to fin an element)

$O(N Log N)$ Linearithmic time ...mergesort quicksort

$O(N^2)$ quadratic time  bubble sort..nested oops ovr the input
